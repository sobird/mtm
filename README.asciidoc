# 商家电商管理后台系统
:toc:

基于 Next.js App Router 的商家管理后台，包含首页仪表盘、营销中心、店铺资料、入驻流程与认证。

## 技术栈

* Next.js 15（App Router、Route Handlers、Server Components）
* React 19 + TypeScript
* Sequelize + SQLite（`sqlite3`）
* NextAuth（Auth.js v5，Credentials 登录）
* TanStack Query、Zustand
* React Hook Form + Zod、Base UI（Dialog/Toast/Select 等）
* Ant Design（仅限 `components/ui` 封装层内部实现，业务页面只从 `@/components/ui` 导入）、Recharts
* Vitest + Testing Library、oxlint / oxfmt

## 环境要求

* Bun 1.4.4（由 `packageManager` 字段固定；可用 `.bun-version` 配合版本管理器）
* Node.js 20+

## 环境变量

[source,bash]
----
DATABASE_PATH=./data/mtm.sqlite   # 可选，默认 ./data/mtm.sqlite
AUTH_SECRET=change-me             # 必填，用于会话与验证码签名
PORT=3000                         # 可选，默认 3000
----

参考 `.env.example`。生产环境必须提供随机的 `AUTH_SECRET`。

## 常用命令

[source,bash]
----
bun install        # 安装依赖
bun run dev        # 开发服务器
bun run build      # 生产构建（standalone 输出）
bun run start      # 启动生产服务（本地调试，生产部署请使用 Docker）
bun run test       # 运行测试（Vitest）
bun run test:watch # 监听模式测试
bun run lint       # oxlint
bun run lint:fix   # oxlint 自动修复
bun run typecheck  # tsc --noEmit
bun run fmt        # oxfmt 格式化
bun run fmt:check  # 格式检查
----

## 目录结构

[source,text]
----
app/            # App Router 路由（(admin)、(auth)、(entry)、api）
components/     # 业务与 UI 组件（ui/ 为基础组件库）
lib/            # 数据库、服务层、认证、校验与通用工具
stores/         # Zustand 状态
styles/         # 全局样式与设计令牌
tests/          # Vitest 测试与测试初始化
data/           # SQLite 数据库文件（运行时生成）
lib/db/seed/data/ # 种子数据（JSON）
----

## 数据库与种子数据

应用启动时通过 `lib/db/seed` 初始化数据库结构并写入 `lib/db/seed/data` 中的种子数据，重复启动不会重复写入。

## Docker 部署

镜像为多阶段构建（Bun 安装/构建 + Node 22 slim 运行），以非 root 用户运行，SQLite 数据存放在 `/data`。Compose 使用命名卷 `mtm-data`，并读取 `.env.production`：

[source,bash]
----
docker build -t ghcr.io/sobird/mtm:latest .
docker compose up -d
curl -s http://127.0.0.1:3000/api/health
# {"code":0,"message":"ok","data":{"db":true}}
----

单副本运行；SQLite 卷只能挂载给一个写实例。容器只绑定 `127.0.0.1:3000`，由宿主机 nginx 反向代理对外提供服务。服务器上的 `.env.production` 必须设置真实的随机 `AUTH_SECRET`（仓库中的同名文件只是模板）。

## CI/CD

`.github/workflows/deploy.yml` 在 `master` 分支推送时执行 lint、typecheck、test、build，然后构建镜像并推送 GHCR（`latest` 与 commit SHA 标签），最后通过 SSH 在服务器执行 `docker compose pull && docker compose up -d`。

nginx 配置也由仓库托管：`deploy/nginx/mtm.conf` 会随部署上传到 `TARGET`，仅当内容变化时才 `install` 到 `/etc/nginx/conf.d/mtm.conf` 并 `nginx -t && systemctl reload nginx`；`nginx -t` 失败会回滚文件并让部署失败。这要求部署用户在 `/etc/sudoers.d/mtm-deploy` 中获得以下免密权限（路径以服务器上 `command -v` 的结果为准）：

----
deploy ALL=(root) NOPASSWD: /usr/bin/install -m 644 * /etc/nginx/conf.d/mtm.conf, /usr/sbin/nginx -t, /usr/bin/systemctl reload nginx
----

需要的仓库 Secrets：`HOST`、`USERNAME`、`KEY`、`PORT`、`TARGET`（服务器上 Compose 文件所在目录）。若 GHCR 镜像为私有，另需 `GHCR_USERNAME`、`GHCR_TOKEN`。
